# FlashFlow 需求说明

## 1. 项目定位

FlashFlow 是一个高并发实时交易平台后端项目，面向秋招作品展示。核心目标是在常见电商能力之上，突出**限时抢购高并发**与**订单状态实时推送**。

## 2. 范围说明

本文档描述产品级功能需求与后续技术规划。当前阶段只做设计文档，不实现接口与业务代码。

## 3. 主要功能

### 3.1 用户登录

- 用户通过账号凭证完成登录。
- 登录成功后获得后续请求所需的身份凭证（如 Token）。
- 未登录用户不能进行下单、抢购、订单查询等需鉴权操作。

### 3.2 商品浏览

- 用户可查看商品列表与商品详情。
- 展示信息包括但不限于：名称、价格、库存/可售状态、商品描述等基础字段。
- 浏览能力面向普通商品；限时抢购商品可单独标识活动信息（开始/结束时间、活动价等）。

### 3.3 普通下单

- 已登录用户针对普通商品发起下单。
- 下单需校验商品存在性、可售状态与库存。
- 下单成功后生成订单，初始状态可查询。

### 3.4 限时抢购

- 在活动时间窗口内，已登录用户可对抢购商品发起抢购下单。
- 需应对高并发访问，保证库存扣减正确、避免超卖。
- 活动未开始、已结束或库存不足时，应明确失败原因。

### 3.5 订单查询

- 已登录用户可查询本人订单列表与订单详情。
- 查询结果包含订单基本信息与当前状态。

### 3.6 实时订单状态

- 订单状态变更后，客户端可近实时感知（例如：已创建、已支付、已取消、已完成等；具体状态集合在实现阶段再细化）。
- 通过实时通道推送状态变更，减少客户端轮询依赖。

## 4. 非功能期望（概要）

- **高并发**：限时抢购场景下支持短时大量请求。
- **一致性**：库存与订单关键路径避免明显超卖与脏写。
- **实时性**：订单状态变更可及时推送到客户端。
- **可部署**：支持容器化部署；编排能力后期可选。

## 5. 后续技术规划

计划使用：

| 技术 | 用途方向 |
|------|----------|
| Gateway | 统一入口、路由、鉴权入口 |
| MySQL | 持久化存储 |
| Redis | 缓存与高并发热点数据 |
| Kafka | 异步消息与事件传递 |
| WebSocket | 实时订单状态推送 |
| Docker | 容器化部署 |

**Kubernetes**：后期可选，当前需求不强制。
